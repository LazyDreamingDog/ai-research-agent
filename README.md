# AI 资料调研助手 Agent

这是一个用 Python 从零实现的 Agent 学习与实践项目。目标是让用户提出一个 AI 相关的研究问题，由助手完成资料搜索、网页阅读、来源核对和结果整理，最终交付一份带引用的中文调研报告。

项目同时服务于两个目标：一是把查找、阅读和核对资料的过程做成可复用的工具；二是通过亲手实现模型调用、工具执行、上下文管理和停止条件，理解一个自定义 Agent 如何工作。

## 当前状态

**目前仅完成项目初始化。** 已有 Python 包结构、命令行帮助和版本信息；模型调用、搜索、网页阅读、来源核对及报告生成均尚未实现。下文描述的是计划实现的能力。

## 它要解决什么问题

围绕一个研究问题，人工调研通常需要反复搜索关键词、打开多个网页、追踪原始出处，再把零散信息整理成结论。过程中还需要判断文章是否只是转述、信息是否过时，以及不同来源之间是否存在矛盾。

这个助手计划把这套过程串起来：保存每个关键判断对应的来源，发现证据缺口时继续查找，最后把已确认的信息、推断和仍未解决的问题一起交给用户。

第一版聚焦公开网页中的 AI 资料，典型任务包括：

- **查找原始出处**：定位某位研究者的发言、原帖或演讲。
- **核对公开信息**：对照官方公告和文档，核对产品功能、发布时间等信息。
- **整理专题资料**：围绕一个技术主题，筛选原始文档、论文和学习资料并形成简报。

## 用户输入什么，会得到什么

用户输入一个问题，可以附带时间范围、关注点或已知链接。例如：

> 帮我找到 Karpathy 关于全球人类使用 AI 分层的原始发言，核对日期和各层人数，并说明这些数字属于个人估算还是正式统计。

预期输出是一份中文报告，包含：

| 内容 | 应当回答的问题 |
| --- | --- |
| 核心结论 | 找到了什么，能回答原问题的哪些部分？ |
| 证据与引用 | 每个关键结论来自哪个网页、原帖或文档？ |
| 来源说明 | 这是原始资料、媒体转述，还是助手的推断？ |
| 不确定性 | 哪些信息有冲突、无法访问，或尚未得到核验？ |

报告计划保存为本地 Markdown 文件，工具调用与来源记录用于回看调研过程。报告内容默认不提交到 Git。

## Agent 如何完成调研

先实现一个单 Agent。模型根据用户目标和已收集的资料选择下一步行动，Python 程序负责执行工具、保存状态和控制任务边界。

1. **明确问题**：提取研究对象、时间范围和需要核对的事项。
2. **检索与阅读**：选择搜索关键词，打开候选网页，优先追踪原始来源。
3. **检查证据**：判断已有资料是否足以支持结论；缺少关键证据时调整关键词或补读来源。
4. **整理报告**：形成回答，把关键结论与来源关联起来。
5. **结束任务**：完成调研后停止；达到步数或时间上限时，输出已有发现并说明未完成的部分。

这里需要亲手实现的核心是“模型决策 → 工具执行 → 结果回传 → 再次决策”的循环。工具返回的网页正文、错误和执行结果都要进入记录，供后续判断使用。

首批计划实现三个工具：

| 工具 | 职责 |
| --- | --- |
| `search_web` | 搜索候选资料，返回标题、链接和摘要。 |
| `read_page` | 读取网页正文及可获得的日期、作者等来源信息。 |
| `save_report` | 将整理好的报告与引用保存到本地。 |

模型供应商、搜索服务和具体数据结构将在功能开发时确定。

## 第一版怎样算完成

- 能从一个真实研究问题出发，完成搜索、阅读和报告保存。
- 报告中的关键事实能追溯到已读取的来源，引用与对应内容相符。
- 遇到搜索失败、网页无法访问或证据不足时，如实记录并说明。
- 保留可检查的工具执行记录，任务能在约定的步数与时间内结束。

使用一组真实问题重复验证这些行为，作为后续修改提示词、工具和模型时的评估依据。

## 本地开发

要求 Python 3.11 或更高版本。

```bash
cd ~/Desktop/ai-research-agent
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
ai-research-agent --help
ai-research-agent --version
```

也可以通过模块入口运行：

```bash
python -m ai_research_agent --help
```

`.env.example` 暂时只记录计划中的配置项；当前代码不读取 `.env`。

## 开发路线

1. 实现最小模型调用与自定义工具调用循环。
2. 接入搜索、网页读取，保存来源信息与工具执行记录。
3. 实现资料补查、中文报告生成与引用核对。
4. 加入最大步数、超时、错误恢复和成本记录。
5. 用真实研究问题评估来源质量、引用准确性和任务完成情况。

## 开发约定

- 初期以理解和实现工具循环为主，依需求逐步引入框架。
- 区分原始来源、转述和推断；资料不足时明确说明。
- 工具失败必须保留真实错误，不生成伪造的搜索结果或引用。
- 密钥、本地配置、运行日志和调研报告不提交到 Git。
